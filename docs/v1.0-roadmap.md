# Statekit v1.0 Roadmap

This document outlines the path to v1.0 - the first stable release of Statekit.

## Current Status (v0.14)

Statekit is feature-complete for most statechart use cases:

| Version | Features |
|---------|----------|
| v0.1-0.2 | Core FSM, hierarchical states, XState export |
| v0.3 | Reflection DSL, struct-based machine definitions |
| v0.4 | History states, delayed transitions, parallel states |
| v0.5 | Invoked services, snapshot/restore |
| v0.6 | Actor model, CLI visualization tool |
| v0.7 | Event persistence, event sourcing |
| v0.8 | Distributed execution, stream locking |
| v0.9 | Code generation, HTTP integration, OpenTelemetry |
| v0.10 | Testing utilities, debug inspector |
| v0.11 | Prometheus metrics, health checks |
| v0.12 | Static analysis, lint rules |
| v0.13 | Eventless/always transitions |
| v0.14 | Plugin system, machine composition, actor persistence |

## v1.0 Goals

### 1. API Stability

**Commitment**: After v1.0, the public API will follow semantic versioning strictly:
- No breaking changes in minor/patch versions
- Deprecation warnings before removals
- Migration guides for major version upgrades

**Actions**:
- [ ] Review all exported types for consistency
- [ ] Ensure type names follow Go conventions
- [ ] Document all public APIs with godoc
- [ ] Mark internal packages clearly (`internal/`)

### 2. Documentation Completeness

**Goal**: Comprehensive documentation for all features.

**Actions**:
- [ ] Complete API reference for all packages
- [ ] Add migration guide from XState
- [ ] Create "Patterns & Recipes" guide
- [ ] Add performance tuning guide
- [ ] Record video tutorials (optional)

### 3. Performance Baseline

**Goal**: Establish performance benchmarks and optimize hot paths.

**Actions**:
- [ ] Create comprehensive benchmark suite
- [ ] Profile memory allocations in hot paths
- [ ] Optimize transition resolution
- [ ] Document performance characteristics

### 4. Test Coverage

**Goal**: Maintain high test coverage with comprehensive edge case testing.

**Actions**:
- [ ] Achieve 90%+ coverage on core packages
- [ ] Add fuzz testing for parsers
- [ ] Add property-based testing for interpreter
- [ ] Create integration test suite

### 5. Breaking Changes (if any)

Evaluate and implement any necessary breaking changes before v1.0:

| Change | Status | Notes |
|--------|--------|-------|
| Review `ir` package exports | Pending | May need to expose more types |
| Unify event types | Pending | `statekit.Event` vs `plugin.Event` |
| Error handling patterns | Pending | Standardize error types |

## Post v1.0 Considerations

Features explicitly deferred to post-v1.0:

### Formal Verification (v1.x)
- Model checking for state machine properties
- Deadlock detection
- Liveness verification
- Integration with TLA+ or Alloy

### Visual Editor Integration (v1.x)
- VSCode extension for machine editing
- Real-time visualization
- Stately.ai integration improvements

### Advanced Persistence (v1.x)
- Full actor state persistence
- Automatic actor restoration
- Distributed actor coordination

## Release Criteria

v1.0 will be released when:

1. **API Stability**: All public APIs reviewed and documented
2. **Test Coverage**: 90%+ on core packages
3. **Documentation**: All features documented with examples
4. **Performance**: Benchmarks established and published
5. **Community Feedback**: Address major issues from early adopters
