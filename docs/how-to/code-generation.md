# Code Generation

Generate Go code from XState JSON definitions using the `statekit generate` command or the `generate` package.

## CLI Usage

```bash
# Generate from XState JSON file
statekit generate machine.json -o machine.go

# With custom package and type name
statekit generate machine.json -p mypackage -t OrderWorkflow -o order.go

# Specify context type
statekit generate machine.json -c "OrderContext" -o order.go

# Read from stdin
cat machine.json | statekit generate -o machine.go

# Output to stdout
statekit generate machine.json
```

### Options

| Flag | Short | Description | Default |
|------|-------|-------------|---------|
| `--output` | `-o` | Output file path | stdout |
| `--package` | `-p` | Go package name | `main` |
| `--type` | `-t` | Type name for the machine | Inferred from filename |
| `--context` | `-c` | Context type name | `struct{}` |

### JSON Types

The generator accepts Statekit Native JSON format:

```json
{
  "id": "order",
  "initial": "pending",
  "states": {
    "pending": {
      "id": "pending",
      "type": "atomic",
      "entry": ["logPending"],
      "transitions": [
        { "event": "SUBMIT", "target": "validating", "guard": "hasItems" }
      ]
    },
    "validating": {
      "id": "validating",
      "type": "atomic",
      "transitions": [
        { "event": "VALID", "target": "processing" },
        { "event": "INVALID", "target": "pending" }
      ]
    },
    "processing": {
      "id": "processing",
      "type": "atomic",
      "transitions": [
        { "event": "COMPLETE", "target": "completed", "actions": ["notifyCustomer", "updateInventory"] }
      ]
    },
    "completed": {
      "id": "completed",
      "type": "final"
    }
  }
}
```

## Generated Output

Running `statekit generate order.json -p orders -t OrderMachine` produces:

```go
// Code generated by statekit generate. DO NOT EDIT.
package orders

import (
    "go.klarlabs.de/statekit"
)

// OrderMachineContext is the context type for the state machine.
// TODO: Replace with your actual context type.
type OrderMachineContext = struct{}

// Action stubs - implement these functions.
func actionLogPending(ctx *OrderMachineContext, e statekit.Event) {
    // TODO: Implement logPending action
}

func actionNotifyCustomer(ctx *OrderMachineContext, e statekit.Event) {
    // TODO: Implement notifyCustomer action
}

func actionUpdateInventory(ctx *OrderMachineContext, e statekit.Event) {
    // TODO: Implement updateInventory action
}

// Guard stubs - implement these functions.
func guardHasItems(ctx OrderMachineContext, e statekit.Event) bool {
    // TODO: Implement hasItems guard
    return true
}

// BuildOrderMachine creates the order state machine.
func BuildOrderMachine() (*statekit.MachineConfig[OrderMachineContext], error) {
    return statekit.NewMachine[OrderMachineContext]("order").
        WithInitial("pending").
        WithAction("logPending", actionLogPending).
        WithAction("notifyCustomer", actionNotifyCustomer).
        WithAction("updateInventory", actionUpdateInventory).
        WithGuard("hasItems", guardHasItems).
        State("pending").
            OnEntry("logPending").
            On("SUBMIT").Target("validating").Guard("hasItems").
        Done().
        State("validating").
            On("INVALID").Target("pending").
            On("VALID").Target("processing").
        Done().
        State("processing").
            On("COMPLETE").Target("completed").Do("notifyCustomer").Do("updateInventory").
        Done().
        State("completed").
            Final().
        Done().
        Build()
}
```

## Workflow

1. **Design** your state machine or write JSON manually
2. **Export** the machine definition as JSON
3. **Generate** Go code with `statekit generate`
4. **Implement** the action and guard stubs
5. **Use** the generated `Build<Type>()` function in your application

### Example Workflow

```bash
# 1. Generate the code
statekit generate order.json -p orders -t OrderMachine -c "OrderContext" -o order_machine.go

# 2. Create your context type and implement stubs
cat > order_context.go << 'EOF'
package orders

import "go.klarlabs.de/statekit"

type OrderContext struct {
    OrderID    string
    Items      []string
    CustomerID string
}

func actionLogPending(ctx *OrderContext, e statekit.Event) {
    log.Printf("Order %s is pending", ctx.OrderID)
}

func guardHasItems(ctx OrderContext, e statekit.Event) bool {
    return len(ctx.Items) > 0
}
// ... implement other stubs
EOF

# 3. Use in your application
cat > main.go << 'EOF'
package main

import "myapp/orders"

func main() {
    machine, _ := orders.BuildOrderMachine()
    interp := statekit.NewInterpreter(machine)
    interp.Start()
    // ...
}
EOF
```

## Supported Features

The generator supports:

- ✅ Basic states and transitions
- ✅ Entry and exit actions
- ✅ Transition actions
- ✅ Guards (conditions)
- ✅ Final states
- ✅ Hierarchical (nested) states
- ✅ Multiple transitions per event

### Hierarchical States

Nested states in JSON are converted to the statekit builder API:

```json
{
  "id": "editor",
  "initial": "idle",
  "states": {
    "idle": {
      "id": "idle",
      "type": "atomic",
      "transitions": [ { "event": "EDIT", "target": "editing" } ]
    },
    "editing": {
      "id": "editing",
      "type": "compound",
      "initial": "typing",
      "children": ["typing", "saving"],
      "transitions": [ { "event": "CANCEL", "target": "idle" } ]
    },
    "typing": {
      "id": "typing",
      "type": "atomic",
      "parent": "editing",
      "transitions": [ { "event": "SAVE", "target": "saving" } ]
    },
    "saving": {
      "id": "saving",
      "type": "atomic",
      "parent": "editing",
      "transitions": [ { "event": "DONE", "target": "typing" } ]
    }
  }
}
```

Generates:

```go
func BuildEditorMachine() (*statekit.MachineConfig[EditorMachineContext], error) {
    return statekit.NewMachine[EditorMachineContext]("editor").
        WithInitial("idle").
        State("idle").
            On("EDIT").Target("editing").
        Done().
        State("editing").
            WithInitial("typing").
            On("CANCEL").Target("idle").
            State("typing").
                On("SAVE").Target("saving").
            Done().
            State("saving").
                On("DONE").Target("typing").
            Done().
        Done().
        Build()
}
```

## Programmatic Usage

Use the `generate` package directly in Go:

```go
import "go.klarlabs.de/statekit/generate"

// Create generator with options
gen := generate.NewGenerator("mypackage", "MyMachine", "MyContext")

// Generate from io.Reader
file, _ := os.Open("machine.json")
code, err := gen.Generate(file)
if err != nil {
    log.Fatal(err)
}

// Write to file
os.WriteFile("machine.go", code, 0644)
```

## Best Practices

1. **Keep JSON as source of truth** - Store your JSON in version control and regenerate Go code when it changes

2. **Don't edit generated code** - Implement actions and guards in separate files; regenerating will overwrite changes

3. **Use meaningful names** - Action and guard names become Go function names (converted to PascalCase)

4. **Organize by domain** - Use `-p` flag to generate into domain-specific packages

5. **Add to build pipeline** - Consider adding `go generate` directives:

```go
//go:generate statekit generate order.json -p orders -t OrderMachine -o order_machine_gen.go
```
